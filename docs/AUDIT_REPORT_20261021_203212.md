# VICTOR comprehensive audit and implementation blueprint

**Audit date:** 2026-10-21  
**Scope:** Current working tree, static source review, local build/test checks, and narrowly scoped local reproductions.  
**Audit mode:** Read-only. No source, configuration, dependency, database, dataset, model, or deployment change was made. This report is the sole file added.

## 1. Executive summary

VICTOR is a promising Next.js 14 / FastAPI Mars traverse planner, but it is **not release-ready** for operational or NASA-data-only claims. The most material issues are:

1. The advertised EVA-duration safety boundary is accepted and displayed, but does not constrain path finding. A 1-hour request returned a 4.462-hour route in a local reproduction.
2. A coordinate outside the 300x300 research extent is silently clamped, and an over-limit starting cell can still yield a route. This changes the requested mission and can permit an unsafe departure.
3. Scenario controls expose weight overrides that the engine ignores; persisted computations lose their request context after restart.
4. The current VERIFIED_SNAPSHOT decision trusts local metadata without verifying cached-grid checksums or a consistent data manifest.
5. The science-priority target catalogue includes published literature sources, which conflicts with the requested exclusive NASA-origin policy. MEDA conditions have no product-level local provenance and include fallback constants.
6. Segment evidence presents a normalized THEMIS brightness proxy as surface material and hard-codes an incorrect CRISM resolution (18 m vs the cache provenance's 181.1424 m).
7. The primary planner has no mobile layout: fixed sidebars and panels consume at least 570 px before the map, while global page scrolling is suppressed. This directly fails the all-device objective.
8. The global map requests a third-party OpenPlanetary CDN at runtime despite the NASA-only policy and has no demonstrated tile-failure state.

No P0 remote exploit, data-destruction path, or confirmed immediate production outage was verified from local evidence. P1 work must be completed before treating a route as an operational/safety result or calling the product NASA-data-only. P2 work is needed for a truthful, accessible, performant all-device release.

## 4. Findings

### P1 — major functional, safety, or data-integrity failures

#### AUD-001 — EVA duration constraint is not enforced

- **Category / severity / confidence:** Backend logic; High; Confirmed.
- **Evidence:** `backend/models/domain.py:32-36` accepts `max_eva_hours`. `backend/services/route_engine.py:87-116` passes the constraints into A*, while its route-time value is only calculated after a path is selected in `backend/services/route_engine.py:353-356`. No time/EVA budget is used to reject a path. `frontend/src/components/panels/CompareScenariosView.tsx:73-76,436-441` represents scenarios as consumables feasibility checks.
- **Observed behavior:** A local compute with a 1.0-hour limit returned a route whose estimate was 4.462 hours.
- **Root cause / impact:** The field is a post-hoc display value, not an admissibility criterion. Users can choose a “strict” mission duration and receive a route exceeding it.
- **Remedy:** Define whether limit means one-way or round-trip EVA, reserve model, turnaround, and time uncertainty. Integrate accumulated travel time into the A* state/cost or enforce a route-budget rejection before a response; report remaining budget and a deterministic “no feasible route” state.
- **Verification:** Unit test a feasible/over-limit boundary, API test all strategies, scenario test, UI copy test, and a mission report assertion that no returned route exceeds its stated limit.

#### AUD-002 — Requested coordinates are silently clamped and the start cell is not safety-validated

- **Category / severity / confidence:** Input validation and routing safety; High; Confirmed.
- **Evidence:** `backend/models/domain.py:10-13` permits arbitrary floats. `backend/utils/mars_geo.py:40-54` clamps coordinate conversion to the grid. `backend/services/route_engine.py:98-105` uses that conversion; `_astar` checks neighbour slope/traversability but not the initial start cell (`backend/services/route_engine.py:178-197`).
- **Observed behavior:** A 20.0526-degree starting cell with a 20-degree limit produced a route. Out-of-extent values are transformed into boundary cells rather than rejected.
- **Root cause / impact:** A route can depart from a cell that violates the stated constraint, and a user may receive a route for a different location than requested.
- **Remedy:** Add finite-number and exact grid-extent validators at the API boundary; return 422 with a useful diagnostic. Validate both start and destination cells against slope/traversability before A*, including no-data state.
- **Verification:** Tests for NaN/Infinity, all four extent edges, outside points, unsafe start, unsafe destination, and returned response coordinates matching accepted request coordinates.

#### AUD-003 — Scenario weight override contract is silently ignored

- **Category / severity / confidence:** API contract/business logic; High; Confirmed.
- **Evidence:** `backend/models/schemas.py:44-48` accepts `weight_overrides`; `backend/services/scenario_engine.py:43-47` reads it but does not pass or apply it. `backend/services/route_engine.py:102-105` always uses static `WEIGHT_PROFILES`.
- **Impact:** API consumers and the UI can believe a scenario changed routing preference when it did not.
- **Remedy:** Either implement a validated, bounded override object that reaches the engine and is recorded in results, or remove the input/control until supported. Avoid untyped strategy names and unknown weights.
- **Verification:** Contract test showing one allowed override changes the expected fixture route/cost, plus tests for invalid strategy/weight values and response echoing effective weights.

#### AUD-004 — Persisted computations discard mission request context

- **Category / severity / confidence:** Cache/persistence correctness; High; Confirmed.
- **Evidence:** `backend/services/computation_store.py:426-455` serializes response material but rehydrates with `request=None`. `backend/routers/scenario.py:28-37` reconstructs a fallback request from the first route/grid center and assumed values when request context is absent.
- **Impact:** A scenario after a process restart can compare a route to altered endpoints/constraints instead of the mission the user submitted.
- **Remedy:** Persist schema-versioned validated request, effective strategy profile, pipeline/data manifest ID, and response version atomically. Refuse scenario comparison for legacy entries that lack the required context.
- **Verification:** Store round-trip test; process-restart integration test; migration/legacy-cache behavior test; report proves same request hash before scenario comparison.

#### AUD-005 — Route cache is not versioned by data, pipeline, or model content

- **Category / severity / confidence:** Cache/data integrity; High; Confirmed.
- **Evidence:** `backend/services/computation_store.py:64-88` cache identity uses coordinates, constraints, and strategies. `backend/routers/route.py:58-74` returns a matching cached result. There is no grid checksum, cache manifest, ingestion date, processing version, or terrain-model version in that identity.
- **Impact:** A route computed from older grids can be returned after ingest/model changes while appearing current and verified.
- **Remedy:** Generate an immutable run manifest containing source product IDs, array hashes, pipeline version, terrain-class model version, and schema version. Include its hash in cache keys and all responses/reports; invalidate incompatible entries.
- **Verification:** Integration test changes a fixture manifest/hash and proves cache miss; report/health endpoint exposes manifest ID; old persisted entries are rejected or explicitly marked legacy.

#### AUD-006 — VERIFIED_SNAPSHOT is declared, not integrity-verified at load

- **Category / severity / confidence:** Data integrity/provenance; High; Confirmed.
- **Evidence:** The ingestion script records array checksums (`scripts/fetch_nasa_data.py:886-925`), but `backend/services/data_service.py:53-80` only checks required arrays exist and have shape 300x300. `backend/services/data_service.py:141-175` accepts a declared `data_mode` from `grid_metadata.json` before its legacy provenance fallback.
- **Impact:** A stale, mismatched, or manually changed grid can be presented as VERIFIED_SNAPSHOT without a startup integrity failure.
- **Remedy:** Add an atomic cache manifest that maps every required/optional grid and auxiliary file to SHA-256, source/product, transform, units, CRS, version, and generated time. Verify it before exposing data; on failure use an explicit invalid/unavailable state rather than a verified label.
- **Verification:** Tamper, missing-file, swapped-provenance, stale-manifest, and partial-write tests; health/UI must distinguish verified, demo, invalid, and unavailable states.

#### AUD-007 — Science-priority model violates the requested exclusive NASA-data policy

- **Category / severity / confidence:** Data provenance/policy; High; Confirmed.
- **Evidence:** `backend/data/cache/science_targets.json:9-120` assigns scores to targets sourced to Goudge, Farley, Mangold, and Ehlmann publications. `scripts/fetch_nasa_data.py:772-832` blends CRISM with that target field and falls back to the target model where CRISM is unavailable. `backend/data/cache/provenance.json:87-98` explicitly identifies “published Jezero literature.”
- **Impact:** Scientific/geospatial domain results are not exclusively NASA-origin even though the UI can claim NASA-only authenticity.
- **Remedy:** Until a NASA-only replacement is verified, remove that field from routing/science priority or label it as unavailable. For enrichment, select direct NASA/PDS products after a separate live provenance validation: record PDS product IDs, labels, observations/sols, coordinates/CRS, processing chain, coverage, and hash. Do not substitute plausible values.
- **Verification:** A policy gate fails the build/ingest if an active domain source lacks an allow-listed NASA/PDS origin. Manual review records the official product identity and transforms for every new field.

#### AUD-008 — Environment response can present unmanifested MEDA values and hard-coded fallbacks as data

- **Category / severity / confidence:** Data provenance/API truthfulness; High; Confirmed.
- **Evidence:** `backend/data/cache/meda_environment.json:20-23` contains only a broad “Sol 1 to 1000 seasonal composite baseline” and citation, not product-level observations or transforms. `backend/services/data_service.py:91-98` loads it opportunistically. `backend/routers/environment.py:35-67` supplies fallback environmental constants. `frontend/src/components/panels/StaticViews.tsx:450-453` claims every value is ingested NASA data or unavailable.
- **Impact:** A regional/environmental display can look measured and verified when it is a fallback or untraceable aggregate.
- **Remedy:** Remove numeric fallbacks for factual environmental conditions. Require a schema-validated MEDA aggregate record with PDS product IDs, sol/time window, location applicability, units, aggregation, missing-data handling, source hashes, and distinction between local observation and regional estimate. Return null/unavailable when absent.
- **Verification:** Missing/invalid manifest test, API null-state test, unit and unit-conversion tests, UI copy test, and data-catalog review.

#### AUD-009 — Segment evidence misrepresents proxy/model data and CRISM resolution

- **Category / severity / confidence:** Data representation; High; Confirmed.
- **Evidence:** `backend/services/evidence_engine.py:10-20,48-53` maps a normalized 0–1 THEMIS night-IR proxy to material/mineral labels. `backend/services/evidence_engine.py:123-130` labels the science score CRISM and reports 18 m. Cache provenance records CRISM at 181.1424 m and says the summary parameters are not mineral abundance (`backend/data/cache/provenance.json:73-84`). `EvidencePopup.tsx:69-196` renders these records as user-facing evidence.
- **Impact:** Users may read interpreted score/proxy classifications as cell-specific measured mineral or surface observations; the resolution is off by roughly a factor of ten.
- **Remedy:** Carry a typed provenance object per displayed value: measured/proxy/modelled/no-data, native and display resolution, coverage, units, transform, and caveat. Do not infer a mineral class from a science-priority tier. Preserve CRISM no-data separately from “no mineral.”
- **Verification:** Fixture tests for measured/no-data/modelled cells; schema and snapshot tests for 181.1424 m; visual test that caveats are visible before any categorical label.

#### AUD-010 — Global explorer uses third-party runtime tiles under NASA-only claims

- **Category / severity / confidence:** Data policy/availability; High; Confirmed.
- **Evidence:** `frontend/src/components/map/GlobalMarsMap.tsx:126-145` uses an OpenPlanetary Carto CDN URL and live NASA Trek endpoints; `:324` says “Real NASA / USGS Data.” The OpenPlanetary service is not a NASA-only data origin, and current code has no source-manifest or demonstrated tile-error recovery.
- **Impact:** The page depends on an external third party, cannot be audited offline, and conflicts with the stated NASA-only scientific/geospatial data policy.
- **Remedy:** Remove the OpenPlanetary basemap. Either ship/cache an approved NASA/PDS-derived global layer with manifest/attribution and compatible CRS, or disable the global explorer until an approved source is available. Add loading, offline, rate-limit, CORS, attribution, and tile-error states.
- **Verification:** Network allow-list test, no-third-party request browser test, offline/error visual tests, source-product audit, and mobile map interaction test.

#### AUD-011 — Application text overstates NASA affiliation and data authenticity

- **Category / severity /confidence:** Content/provenance; High; Confirmed.
- **Evidence:** `frontend/src/components/panels/StaticViews.tsx:141-182` calls the app a NASA Mars Exploration Program experience, says it was developed for NASA MEP, and says all datasets are authentic NASA PDS products. This conflicts with AUD-007 and AUD-008. `CompareScenariosView.tsx:240,258,594` claims an HRSC limit, Tobler terrain adjustment, and HiRISE geologic contacts not evidenced by the route engine/active ingestion.
- **Impact:** It can imply NASA endorsement and stronger scientific basis than the implementation supports.
- **Remedy:** Replace affiliation language with accurate independent-project wording; generate source/method statements from validated metadata rather than static prose; add content review as a release gate.
- **Verification:** Repository content scan for prohibited/unsupported assertions, legal/brand review, and UI assertions against active data manifest.

### P2 — significant reliability, usability, performance, or coverage work

#### AUD-012 — Primary UI is structurally desktop-only

- **Category / severity / confidence:** Responsive UI; High; Confirmed.
- **Evidence:** Every primary state uses `h-screen overflow-hidden` (`frontend/src/app/planner/page.tsx:499-663`); global `html, body` also suppresses scrolling (`frontend/src/app/globals.css:240-243`). The sidebar is 210 px (`components/sidebar/Sidebar.tsx:60-62`), inspector 360 px (`planner/page.tsx:1159-1161`), and bottom panels include fixed 220/240 px widths and 220 px height (`:928-1073`). `EvidencePopup.tsx:38-40` fixes its width at 320 px. No responsive media/container strategy was found.
- **Impact:** On a 320–430 px screen the permanent columns alone exceed the viewport; controls and content become clipped with no valid page-scroll escape.
- **Remedy:** Adopt a mobile-first layout contract: single primary content column, collapsible/drawer navigation, bottom sheet inspector, horizontally safe charts/tables, viewport/safe-area aware map controls, and scoped overflow. Use CSS breakpoints/container queries and avoid fixed desktop widths as structural layout.
- **Verification:** Automated screenshot + interaction matrix at 320, 360, 375, 390, 412, 768, 1024, 1280, 1440 CSS px; portrait/landscape; keyboard open; 200% zoom; touch and mouse; iOS safe-area simulation.

#### AUD-013 — Accessibility semantics and focus behavior need remediation

- **Category / severity / confidence:** Accessibility; Medium; Confirmed from source, unverified with assistive technology.
- **Evidence:** Interactive route-selection table rows are rendered as clickable table content in `frontend/src/components/panels/RouteComparisonTable.tsx:50-64` and `RouteAnalysisView.tsx:489-500`, rather than native buttons/links. The fixed hidden-overflow shell compounds focus visibility and reflow risk. Evidence popup/dialog behavior is an absolutely positioned panel without demonstrated focus trap/return (`EvidencePopup.tsx:38-61`).
- **Impact:** Keyboard and screen-reader users may not be able to discover, operate, or exit interactive data views reliably.
- **Remedy:** Use semantic buttons/links, visible focus styles, roving focus only where justified, proper dialog semantics/focus return for modal behavior, labelled controls, chart/table text alternatives, and reduced-motion support.
- **Verification:** axe/lint gate; keyboard-only walkthrough; NVDA/VoiceOver tests; 400% reflow; contrast and focus-visible screenshots.

#### AUD-014 — Tile-generation claims conflict with the available input

- **Category / severity / confidence:** Map/data resolution; Medium; Confirmed.
- **Evidence:** Provenance says the full CTX mosaic is used for map tiles (`backend/data/cache/provenance.json:45-56`), but `scripts/generate_tiles.py:254-260` builds imagery tiles from `imagery.npy`, and ingest creates that array by decimating to 300x300 (`scripts/fetch_nasa_data.py:691-710`).
- **Impact:** UI wording such as “~5 m/px” can be read as rendered map detail when available tile generation uses the grid array. Upscaling cannot restore source detail.
- **Remedy:** Correct provenance/UI wording to the effective grid/tile resolution, or retain and tile approved full-resolution imagery with explicit storage/performance budgeting and manifest linkage.
- **Verification:** Inspect generated tiles against source dimensions; visual resolution test; metadata assertion proving displayed layer resolution.

#### AUD-015 — ML terrain classifier has no performance evidence or reproducible artifact

- **Category / severity / confidence:** ML lifecycle; Medium; Confirmed.
- **Evidence:** `scripts/classify_terrain.py:60-98` median-imputes CRISM gaps; `:110-135` chooses K using silhouette on a random training sample; `:217-233` fits K-means; `:259-284` outputs labels/JSON but no persisted model, scaler, held-out metrics, spatial validation, or uncertainty report.
- **Impact:** The four terrain archetype labels can be useful exploratory clusters, but their semantic reliability, stability, and generalization are unproven. They must not be described as best-performance ML.
- **Remedy:** Define the task and ground truth first. Establish a NASA-only evaluation dataset if one can be officially sourced; otherwise present results as unsupervised exploratory clusters. Add spatially blocked validation, seed/bootstrap stability, coverage-stratified results, preprocessing/version artifacts, model card, baseline comparison, and unknown/no-data handling.
- **Verification:** Pre-registered acceptance metrics appropriate to the task; held-out spatial results; stability threshold; reproducible run from manifest; independent review of semantic cluster naming.

#### AUD-016 — Critical test coverage omits negative/safety/data-integrity cases

- **Category / severity / confidence:** QA; Medium; Confirmed.
- **Evidence:** Existing tests pass, but `backend/tests/test_api.py` primarily exercises successful lifecycle behavior and non-null environment values; `test_route_engine.py` does not reject unsafe initial cells or enforce EVA budget; persistence/scenario/data-manifest/weight-override cases are absent.
- **Impact:** The suite gives a green signal while the proven P1 defects remain possible.
- **Remedy:** Add tests for every finding’s verification method before or with the fix; require branch coverage of validators and explicit falsification tests, not just happy-path snapshots.
- **Verification:** CI quality gate reports unit, API, persistence, visual, accessibility, performance, and provenance suites separately; known bad fixtures must fail.

#### AUD-017 — Route/scenario endpoints run CPU-bound work in async handlers

- **Category /severity / confidence:** Performance/reliability; Medium; Confirmed.
- **Evidence:** `backend/routers/route.py:34-82` and `backend/routers/scenario.py:12-54` are async endpoints but directly invoke synchronous Python routing; `route_engine.py:87-208` contains A* work. The route router itself notes multi-second desktop computation (`route.py:40-46`).
- **Impact:** Under concurrent requests, a worker can block response handling and make map/status interactions appear failed. There is no evidence of rate limiting, work queue, cancellation, or request budget.
- **Remedy:** Benchmark with realistic grid/strategy sets; move CPU-bound jobs to a controlled worker/process boundary or bounded executor; add timeouts, cancellation/queued status, cache observability, and rate limits appropriate to deployment.
- **Verification:** Load tests at target concurrency, p95/p99 latency/SLOs, timeout behavior, cancellation, cache-hit/miss metrics, and no event-loop starvation.

#### AUD-018 — Documentation/method descriptions have drifted from implementation

- **Category / severity / confidence:** Documentation/reliability; Medium; Confirmed.
- **Evidence:** `StaticViews.tsx:94-96` says “negative science value,” whereas route cost applies a science penalty model; `CompareScenariosView.tsx:258` says Tobler terrain-adjusted while actual time is derived from distance, walking speed, and mean traversability (`route_engine.py:353-356`). The README/test/status documentation counts also differ from the current 72 passed/4 skipped run.
- **Impact:** Users and maintainers may make decisions from a different algorithm/data contract than the executable system.
- **Remedy:** Make documentation generated or validated from structured engine/provenance metadata; add a release doc-review checklist and tests for key copy-to-model contract claims.
- **Verification:** Docs CI checks current test commands/results and a set of canonical claim assertions; manual review of user-facing safety language.

### P3 — nonblocking cleanup and optimization

#### AUD-019 — Cache key precision is poorly aligned to the grid

- **Category / severity / confidence:** Performance/maintainability; Low; Confirmed.
- **Evidence:** Cache keys use raw coordinate precision (`computation_store.py:64-88`) while the route grid has 300x300 cells across the stated extent.
- **Impact:** Small coordinate changes that land in the same grid cell can miss the cache, wasting compute.
- **Remedy / verification:** Key routing geometry by accepted start/destination cell plus manifest and constraint hashes, retaining original requested coordinates separately; benchmark hit rate without conflating requests.

#### AUD-020 — API client typing can be tightened

- **Category / severity / confidence:** Maintainability; Low; Confirmed.
- **Evidence:** The frontend API layer includes generic record-shaped paths alongside richer TypeScript domain types.
- **Impact:** Contract drift is easier to introduce.
- **Remedy / verification:** Generate or share schemas from OpenAPI, eliminate opaque records for supported endpoints, and type-check contract fixtures in CI.

## 5. NASA-only provenance, completeness, and enrichment plan

### Current local source account

| Data/layer | Local record says | Audit state |
|---|---|---|
| MOLA elevation/slope/traversability | MGS/MOLA, with 463 m native limitation | Locally documented; external authenticity not checked in this audit. |
| THEMIS night-IR proxy | Mars Odyssey; normalized brightness proxy | Locally documented; must remain a proxy, not thermal inertia/material measurement. |
| CTX imagery | MRO CTX; decimated 300x300 cache | Provenance/tile implementation conflict must be resolved. |
| CRISM indices | MRO CRISM MRDR; about 66% measured coverage | Locally documented; preserve no-data and correct display resolution. |
| Science priority | CRISM plus published Jezero target literature | **Not NASA-only** under requested policy. |
| MEDA environmental values | Broad citation and seasonal baseline | **Unverified/incomplete provenance**; do not expose as verified measurement. |
| Global explorer OPM basemap | OpenPlanetary CDN | **Not NASA-only** and runtime external dependency. |
| Terrain archetypes | VICTOR K-means derived from local grids | Derived, no performance validation or model artifact. |

### Enrichment sequence (do after approval, with live source validation)

1. Establish a data governance registry: allow-listed NASA/PDS nodes, source owner, PDS product ID, label URL, retrieval time, license, CRS, units, spatial/time coverage, checksum, transform version, and status.
2. Replace or disable literature target scores. Consider direct NASA/PDS Mars 2020/CRISM products only after recording authoritative product identity, coverage, and a reproducible join to the grid. If no suitable NASA-only target layer exists, show “not available”; do not manufacture an equivalent.
3. Rebuild MEDA environmental representation from verified NASA/PDS records with sol/time and local applicability. Keep environmental observations separate from grid-wide traverse conditions.
4. Keep source-resolution fields through every transform. A grid resample must carry both native and effective display/routing resolution.
5. Require per-cell data state: measured, derived, modelled, unavailable, and invalid. Null/no-data must never become a plausible number.
6. Build atomic versioned manifests and reproducible ingest checks before considering new datasets or ML features.

### Task-level acceptance checklist

- **R-01 Bounds and finite values:** API rejects invalid input before coordinate conversion; response never changes accepted point.
- **R-02 Endpoint safety:** start/destination traversability/slope/no-data status are validated and explained.
- **R-03 EVA budget:** time is computed using documented assumptions and prunes/rejects over-budget routes.
- **R-04 Scenario contract:** every submitted constraint and effective weight appears in response metadata and drives computation.
- **D-01 Manifest:** a single checksummed logical bundle links grids, metadata, targets, environment, tiles, model artifacts, and source records.
- **D-02 Source policy gate:** active scientific/geospatial inputs must have a NASA/PDS allow-list record; derived data names all inputs.
- **D-03 Missing data:** invalid, absent, modelled, and measured states remain distinct end-to-end.
- **E-01 Evidence schema:** UI cannot render a modelled/proxy value as direct measurement.
- **U-01 Reflow:** no two-dimensional scrolling, clipped controls, or permanent desktop columns on narrow screens.
- **M-01 Model card:** task, data, preprocessing, seed, selection criteria, coverage, limitation, and validation results are retained with output.
- **O-01 Performance:** define and meet cold/cache-hit p95, concurrency, error-rate, memory, and cancellation targets in the actual deployment configuration.

## 8. Test and release-verification strategy

### Automated

- Unit: validators, endpoint grid safety, time budget, cost/effective weights, no-data handling, manifest/checksum rules, all transformations/unit conversions.
- API/integration: route, scenario, persisted-computation restart, report generation, tile errors, health state, stale cache rejection, null environment/source responses.
- Contract: OpenAPI/client types; every displayed source field must derive from API manifest data.
- Data: fixture manifests with known hashes; coordinate/CRS/resolution assertions; duplicate/stale/mismatched-source fixtures.
- ML: deterministic pipeline replay, spatially blocked split, bootstrap stability, coverage-stratified performance, documented baselines.
- Frontend: browser workflows for loading, API failures, empty states, map/layer behavior, download/print, and keyboard interactions.
- Accessibility: axe gate plus keyboard and screen-reader manual scripts.
- Performance: concurrent compute and mixed cache-hit/miss load runs in production-like deployment.

### Required viewport/device matrix

| Class | Required widths / conditions |
|---|---|
| Small phones | 320, 360, 375, 390, 412 px; portrait and landscape; keyboard open. |
| Tablets | 768 and 1024 px; portrait and landscape. |
| Desktop | 1280, 1440, and 1920 px. |

### Release blockers

1. Any route violates an accepted mission constraint or silently changes coordinates.
2. Any active science/geospatial source lacks verified NASA/PDS policy approval.
3. Any verified data bundle starts with hash/provenance mismatch.
4. A proxy/model/no-data value is visually represented as a measured value.
5. Any primary workflow fails required small-phone/touch/keyboard tests.
6. Critical P1 regression, manifest, scenario-restart, and report tests are absent or failing.

## 9. Risks, unresolved questions, and stop/ask rules

- Local provenance claims were assessed only against repository evidence. Product authenticity, availability, licensing, and current NASA/PDS access must be validated in a separate approved network-enabled phase.
- No deployed URL, database contents, real credentials, authentication/authorization policy, or production logs were available for this read-only audit. Security and operational claims remain unverified.
- Browser, print/PDF, screen-reader, actual mobile hardware, and real map-tile behavior remain unverified pending an approved test environment.
- The working tree already contained uncommitted changes before this report; they were preserved and not attributed to this audit.
- Ask for product direction before choosing an EVA reserve model, whether science priority must remain a routing factor, whether global imagery may be bundled, and which NASA/PDS products are authorized for each requested enrichment.

## 10. Audit conclusion

The next implementation should begin with mission correctness and data truthfulness, then make the now-trustworthy interfaces responsive. Cosmetic device styling alone would hide the most serious defects rather than make VICTOR bullet-proof. No remediation has been started in this audit phase.
